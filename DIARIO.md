12/11/2026
Primeiro dia de desenvolvimento e logo após receber o desafio e ler atentamente o enunciado, parti para brainstorming de ideias. Esse processo começou comigo a pensar em necessidades pessoais que poderiam transformar-se em apps, mas posteriormente passou a inquirir os meus pais para saber se haveria alguma necessidade que teriam ou então apenas alguma ideia interessante. Deste brainstorming inicial surgiram 2 ideias que considerei interessantes:
  - Aplicação de apresentação em tempo real dos autocarros da STCP num mapa.
    - Problema: Fontes oficias da STCP disponibilizam a informação sobre chegada de autocarros de forma pouco intuitiva: Um website de difícil navegação que apresenta uma estimativa em minutos para o autocarro chegar à paragem. As paragens possuem QR codes que redirecionam para lá, mas devido ao pouco tamanho que possuêm, com menor luminosidade a leitura é dificultada.
    - Solução: Utilizar a informação já disponibilizada pela STCP e apresentá-la numa App que dê para verificar as paragens mais próximas do utilizador e o tempo estimado de chegada (ao invés de apenas verificar quando chegar à paragem), um mapa interativo que mostre a localização aproximada do autocarro baseado no tempo de chegada e um perfil de utilizador para que possa guardar as paragens favoritas e facilitar a consulta.
  - Aplicação de apresentação em tempo real do fluxo de turistas no Porto.
    - Problema: Grandes fluxos inesperados de turistas, podem levar a problemas logísticos (stocks de cafés mal abastecidos, transportes públicos insuficientes, ...)
    - Solução: Utilizar a informação disponibilizada por aplicações de rastreamento de voos, para saber influxo de pessoas a aterrar no aeroporto Sá Carneiro de forma a criar antecipadamente estimativas de turistas esperados na cidade a certa data.

13/11/2026
Com incertezas de que ideia seguir, decidi criar um google forms e enviar a amigos e conhecidos de diversas áreas, de forma a obter sugestões de ideias de aplicações que pudessem resolver algum problema dentro da sua área profissional ou pessoal. Das pessoas a que o forms foi enviado, estão incluídos profissionais da área agrícola, organização de eventos e musical de idades entre os 25-50 anos. O forms criado foi o seguinte: https://forms.gle/WkysGwR4KhYG45GH7

16/11/2026
Verifiquei as respostas ao formulário e apenas obtive 1, que foi: "Ajudar a rede a tecer rede!!!". Entre essa ideia e as outras que já tinha pensado, decidi avançar com a ideia de apresentar a localização dos autocarros STCP. Pedi ao ChatGPT que stack ele recomenda para a implementação (ver prompts.md) e a sugestão que recebi foi: React Native + Expo para aplicação android; React + Next.js para PWA; NestJS + TypeScript para API; Postgres com PostGis para base de dados; Redis para cache em tempo real; Além de me ter dado um recurso importante disponibilizado pela Porto Dados Abertos: Os dados de paragens e autocarros da STCP em GTFS: https://dadosabertos.cm-porto.pt/pt_PT/dataset/horarios-paragens-e-rotas-stcp?utm_source=chatgpt.com

17/11/2026
Ao ver melhor a resposta que o ChatGPT me deu, também verifiquei que ele sugeriu-me usar o docker, então questionei (ver prompts.md) que vantagens teria mesmo que estivesse a trabalhar sempre no mesmo dispositivo e ele apontou que ajudar-me-ia a isolar as dependências para o meu projeto, então prosegui à instalação do docker e configuração do ficheiro .yml

18/11/2026
Depois de configurar o docker, comecei a incializar a base de dados postgres, mas quando me tentava conectar, dava erro. Ao esclarecer com o ChatGPT, o problema era que tinha uma instalação do postgres17 com o docker e uma instalação do postgres18 com o Homebrew na mesma porta e estava a haver conflito, mas após ir ao terminal e correr "brew services stop postgresql@18" já consegui fazer a conexão à base de dados. Após isso, ao pensar no tempo limitado que tinha, decidi abandonar a ideia de criar uma app nativa de android e apenas fazer uma PWA, então pedi ao ChatGPT para me dar uma estrutura completa e o passo a passo para inicializar o frontend e backend (ver prompts.md). Com os vários códigos de terminal para criar pastas e inicializar NestJS, Next.js, react e uma nova sugestão: Prisma, realizei um teste na API para devolver hello world que funcionou.

19/11/2026
Com a estrutura da app já feita, prossegui a fazer deploy no vercel mesmo com a app e API nas predefinições. Inicialmente estava com dúvidas se era correto fazer deploy da API no Vercel, mas após verificar projetos anteriores que tinha feito o mesmo e a ter dificuldades em fazer deploy em qualquer outra plataforma, prossegui com o vercel e tive sucesso. Após o deploy, comecei a fazer o login, onde tive de aprender a usar o prisma e a atualizar a base de dados localmente, que inicialmente deu erro pois o meu contract.prisma não continha a tabela sptafial_refs_sys que o postgis colocou automaticamente, pedindo ajuda ao chatgpt para me as definir e fazer a migração local e posteriormente a aprender como passar as migrações para o Supabase, onde criei a tabela utilizador. Também tive de habituar às sintaxes e fluxo do Nest.js que nunca tinha usado, aprendendo a mexer com os controllers, services e modules de forma a criar endpoints. Após isso pedi ao codex para criar páginas de frontend para registro e login que chamassem os endpoints criados.

21/11/2026
Com o login já a funcionar, passei a guardar a sessão com tokens JWT, criando um endpoint /me que lia o token e verificava se o utilizador tinha sessão inciada e autorização para aceder ao website. Também foi criado o componente da página de autenticação para não ter o mesmo código de página em Login e Registrar. Esse componente foi criado pelo codex (ver prompts.md)

23/11/2026
Ao perceber que os deployments estavam a ter erro no vercel, investiguei o problema com ajuda do codex e percebi que tinha ficheiros package.json a mais que estavam a causar conflitos no deployment, então removi-os e passei todas as dependências para o package.json da raiz do projeto. Após isso, configurei direito as variáveis de ambiente no deployment para poder criar os cookies corretamente, tirando a sameSite security em deployment, já que ao contráro do desenvolvimento em localhost, a API e o frontend ficam com urls diferentes. Com isso feito, instalei a biblioteca MapLibre GL para apresentar um mapa na aplicação e pedi ao codex para que me o gerasse a mostrar pontos de paragens hard-coded.

24/11/2026
Com um mapa e paragens a apresentar, faltava mostrar um autocarro. Ao pesquisar como calcular a localização baseada em tempos estimados disponibilizados no site da STCP, descobri que a porto digital disponibiliza um endpoint público que devolve as coordenadas de todos os autocarros em tempo real em: https://broker.fiware.urbanplatform.portodigital.pt/v2/entities?q=vehicleType==bus. Então criei uma função que fosse buscar apenas o autocarro 204, através de parâmetros dentro do url e que a cada 30 segundos verificasse se havia atualização de localização e caso houve-se, atualizar a posição no mapa.

25/11/2026
Ao pensar melhor em como buscar as coordenadas dos autocarros, com a ajuda do codex, troquei a função para verificar as coordendas a cada segundo, mas apenas devolvê-las caso haja alteração. Como já tinha autocarros e paragens a serem apresentadas hard-coded, passei a criar tabelas na base de dados para rotas e paragens, criar endpoints CRUD para eles, popular através do Bruno e fazer com que a função de buscar autocarros fosse buscar 1 autocarro da linha dentro da base de dados e o apresenta-se. Após isso, passei a apresentar vários autocarros da mesma linha, utilizando o id disponibilizado pela API da Porto Digital para os diferenciar. Após isso fiz o mesmo para mostrar as paragens da base de dados e não hard-coded. Como já tinha paragens e autocarros a mostrar, passei a criar uma tabela de relação entre linhas e paragens, para se poder saber que linhas passavam em cada paragem específica. Como estava a funcionar com as minhas 2 linhas e 2 paragens de teste, troquei os endpoints de criação para que recebessem requisiçoes em bulk e pedi ao codex para pegar nos ficheiros disponibilizados pela Porto Dados Abertos com as informações GTFS das paragens e linhas de autocarro para criar-me ficheiros JSON que eu pudesse colocar no Bruno e popular a base de dados, além de pedir para ele verificar as relações entre paragens e linhas e que me criasse ficheiros JSON para poder definir as relações. Antes de popular a base de dados, criei uma sidebar onde se podia selecionar que autocarros se quer ver a localização e passei para a população, tendo um mapa com todas as paragens, linhas e relações da STCP.

26/11/2026
Fiz ajustes finais: Cluster nas paragens para não apresentarem todas ao mesmo tempo; Barras de pesquisa de paragens e linhas; lista de linhas favoritas do utilizador e ajustes para a sidebar ficar bem no mobile.
